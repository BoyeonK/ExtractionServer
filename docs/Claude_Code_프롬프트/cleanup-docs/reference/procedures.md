# 재배치 절차

## 안전한 이동 순서

```
Identify
    ↓
Classify
    ↓
Create destination if necessary   ← GATE 2
    ↓
Copy / Rewrite
    ↓
Verify
    ↓                             ← GATE 3
Remove / Reduce old copy
```

**새 위치에 먼저 반영하고, 정보가 충분히 보존되었는지 확인한 뒤, 기존 위치에서 제거하거나 축약한다.**

재배치가 필요한 경우 핵심은 **먼저 보존하고 나중에 제거하는 것**이다.

---

## Verify 체크리스트

- 중요한 contract가 빠지지 않았는가
- invariant가 의미상 보존되었는가
- reference가 올바른가
- 새 위치만 읽어도 해당 문서의 역할 안에서 이해 가능한가
- 기존 위치에서 제거한 뒤 탐색 경로가 끊기지 않는가

---

## 목적지가 없을 때

예: Bootstrap에 특정 런타임 설명이 길게 있는데 그 컴포넌트의 Design 문서가 없음

**기존 내용을 먼저 삭제하지 않는다.**

```
정보의 역할 식별
→ 적절한 문서/섹션이 필요한지 판단
→ 필요하면 목적지 신설        ← GATE 2
→ 정보 이동
→ 검증
→ 기존 위치 축약/삭제          ← GATE 3
```

### 신설 기준

새 문서는 단순히 옮길 곳이 필요하다는 이유만으로 만들지 않는다.

```
현재 cross-file 동작     → Design 문서 후보
중요한 결정 rationale    → ADR 후보
아직 결정되지 않은 문제  → Open Questions
결정된 작업 진행 상태    → Issue Tracker / Progress Log
repo-wide 작업 규칙      → Bootstrap
local correctness        → 코드 주석
```

기존 문서나 섹션으로 충분히 역할을 수행할 수 있으면 새 문서를 만들지 않는다.

---

## 문서와 코드가 다를 때

각 매체의 역할이 다르다.

```
코드   → 현재 실제로 실행되는 구현
Design → 현재 시스템이 따라야 하는 의도된 계약
ADR    → 결정 당시의 이유와 전제
Test   → contract/invariant를 실행 가능한 형태로 검증
```

**어느 한쪽을 자동으로 정답으로 보지 않는다.**

### 확인 순서

1. 불일치가 있다는 사실을 먼저 알린다
2. 코드의 현재 동작을 확인한다
3. Design의 현재 계약을 확인한다
4. 관련 ADR의 배경을 확인한다
5. 테스트가 실제로 무엇을 보장하는지 확인한다
6. 차이가 생긴 원인을 구분한다
7. 근거가 충분할 때만 수정한다

### 원인 후보

- 구현이 Design을 위반했는가?
- Design이 코드 변경을 따라가지 못했는가?
- 새로운 결정이 기록되지 않았는가?
- migration 중인 상태인가?
- 테스트가 오래된 계약을 검증하고 있는가?

ADR은 과거 기록이므로 현재 코드와 다르다는 이유만으로 구현에 맞춰 고치지 않는다.

**원인을 확정할 수 없으면 임의로 한쪽을 맞추지 않고 보고한다.**

---

## 되돌리기 가능성

정리 작업은 다음을 만족해야 한다.

- diff만 보고도 어떤 정보가 어디로 이동했는지 추적 가능
- version control history로 원래 내용 복구 가능
- 한 번에 너무 많은 역할의 문서를 동시에 재구성하지 않음

**기존 정보의 이동·축약·삭제가 주목적인 작업은 기능 변경과 분리한다.**

(기능이나 설계 변경에 직접 수반되는 문서 갱신은 그 변경과 같은 작업 단위에서 해도 된다. 여기서 말하는 것은 대규모 갈무리다.)

핵심은 커밋 형식이 아니라 **정리 작업이 reviewable하고 reversible한 상태를 유지하는 것**이다.

---

## 정리 후 확인

작업자가 코드를 읽을 때 이 흐름으로 문맥을 확장할 수 있어야 한다.

```
Bootstrap
    ↓
현재 코드 / 관련 Design
    ↓
현재 Contract / Invariant
    ↓
Reference 발견
    ↓
필요한 ADR
```

깊은 문맥은 항상 먼저 읽는 것이 아니라 필요할 때만 따라간다.

정리가 끝난 뒤 확인할 것:

- Bootstrap에서 새 문서로 가는 경로가 연결되었는가
- 끊긴 참조가 없는가
- 현재 규칙이 쉽게 발견되는 위치에 있는가
- 오래된 설명이 현재 작업을 방해하지 않는가
- 저장소의 문서 검증 도구(Markdown lint, link checker, doc build)가 통과하는가
